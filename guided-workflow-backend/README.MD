# Backend Quickstart

## Requirements

### Python
- install Python 3 from https://www.python.org/downloads/
- See [pyproject.toml](./pyproject.toml) for python version. Example:
  ```toml
  [project]
  requires-python = ">=3.10"
  ```

### Package Managers

- [uv](https://docs.astral.sh/uv/) is highly recommended, and is the de-facto package manager for the project.

#### UV Installation
Linux / Mac
```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Windows
```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

- If you intend to contribute to the project, install pre-commit hooks

## Project Settings and Environment

``AppSettings`` in ``settings.py`` will configure itself given the correct environment.
- Ensure that the ``.env`` file is in the root directory of the project. This is not checked into source control.
- If an ``.env`` file is not present, ``pydantic`` will look for environment variables. This is the desired behavior for production.
- For development, ask a team member for the ``.env`` file.

- Download and install [awscli](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html)
- Configure the CLI. Note you will not have a AWS Access Key ID or Secret Access Key. These can be remain blank.


#### Install Duo SSO
- Download the Duo SSO binary from [ATS-operations/duo-sso](https://wwwin-github.cisco.com/ATS-operations/duo-sso/releases). Pick the appropriate version for your OS.
- You should create a dedicated directory for the binary. Add this directory to your PATH. Move the binary and rename it to `duo-sso`
- Create a directory, `~/.config/duo-sso`. This is where the configuration file will be stored. Create a file, `~/.config/duo-sso/config.json` with the following contents:
```json
{

  "partner_spid": "https://signin.aws.amazon.com/saml",
  "aws_urn": "https://signin.aws.amazon.com/saml",

      "aws_role_name": "devops",
```

#### Update Git Config
- Authentication via Git requires the use of aws codecommit credential-helper. To enable this, modify your global git config


## Kubectl

- install kubectl https://kubernetes.io/docs/tasks/tools/install-kubectl/. The  version should match the EKS cluster version or be at least one minor version away. 
- Use awscli to list the available EKS clusters
```bash
aws eks list-clusters
```

- Use awscli to get the kubeconfig for the desired cluster
```bash
aws eks update-kubeconfig --name $CLUSTER_NAME
```
### Exporting requirements

```bash
uv export --no-hashes --no-dev --no-annotate --extra server > requirements.txt && git add requirements.txt 
```

## Extending
 
It is recommended that an API definition be written in OpenAPI format. This can be used to generate client code in many languages.
Most importantly, it can be used to quickly generate data classes for the client and backend.

Python
```bash
# install the code generator in a separate environment
pip install datamodel-code-generator
datamodel-codegen \
--input $INPUT_FILE \
--output $OUTPUT_FILE \
--output-model-type pydantic.BaseModel \
--base-class V2BaseModel \
--use-standard-collections \
--target-python-version 3.10 \
--use-subclass-enum
```

## Versioning

- The canonical version is tracked by poetry in ``pyproject.toml``.
- Use semantic versioning for releases.
  - Major: Breaking changes 1.0.0
  - Minor: New features 0.1.0
  - Patch: Bug fixes 0.0.1

- The version tag should be tracked with git tags
```bash
git tag -a vX.X.X -m "Release X.X.X"
git push origin vX.X.X
```
